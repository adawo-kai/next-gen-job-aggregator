Ниже представлено готовое техническое задание на разработку умного агрегатора вакансий нового поколения.
Поскольку обычных парсеров сейчас действительно много, в ТЗ заложены конкурентные преимущества (киллер-фичи), которые выделят проект на фоне аналогов и покажут работодателям высокий инженерный уровень: AI-анализ вакансий, умная дедупликация между площадками, защита от накруток и трекер откликов.

Техническое задание: Умный агрегатор IT-вакансий (Next-Gen Job Aggregator)


1. Цель проекта

Разработать бэкенд-сервис для автоматического сбора, очистки, обогащения и поиска IT-вакансий из множества источников. В отличие от классических агрегаторов, система должна не просто копировать объявления, а убирать межплощадочные дубли, оценивать качество вакансии с помощью LLM и подбирать предложения под резюме кандидата.

2. Источники данных (Сбор и парсинг)

Система должна поддерживать модульную архитектуру коллекторов (парсеров), чтобы новые источники можно было добавлять без переписывания ядра:
• Официальные API: интеграция с открытым API (например, hh.ru API).
• Веб-скрапинг: сбор данных с профильных сайтов без открытого API (например, Habr Карьера или локальные джоб-борды).
• Telegram-каналы: чтение публичных каналов с вакансиями через Telegram API (MTProto) или парсинг веб-превью.
Требования к сбору:
• Запуск по расписанию (раз в 15–30 минут) через планировщик и очереди задач.
• Изоляция воркеров: ошибка или блокировка на одном сайте не останавливает сбор с остальных.
• Соблюдение лимитов запросов (Rate Limiting), ротация User-Agent и механизм повторных попыток (Retry с экспоненциальной задержкой).

3. Улучшенные функции (Конкурентные преимущества)


3.1. Умная межплощадочная дедупликация

Обычные парсеры проверяют только URL. Если компания выложила одну вакансию на hh.ru и в Telegram, пользователь увидит её дважды.
• Задача: объединять одинаковые вакансии с разных площадок в одну сущность, сохраняя список всех ссылок-источников.
• Реализация: генерация нормализованного хеша (компания + очищенный заголовок + ключевые навыки) и проверка текстовой схожести (например, через триграммы в PostgreSQL или векторные эмбеддинги).

3.2. AI-обогащение и оценка «воды» (LLM Pipeline)

Сырой текст вакансий часто перегружен шаблонами и не содержит чётких требований.
• Задача: пропускать новые вакансии через LLM API для извлечения структурированных данных.
• Что извлекаем:
	• Реальный стек технологий (массив тегов).
	• Точный грейд (Intern, Junior, Middle, Senior, Lead), даже если он не указан в заголовке.
	• Краткое саммари в 3 пункта: «Что делать», «Что требуют», «Условия».
	• Индикаторы «красных флагов» (например, неоплачиваемое тестовое, переработки, размытые обязанности).

3.3. Умный матчинг с профилем кандидата

• Задача: пользователь загружает своё резюме или список навыков, а система рассчитывает процент совпадения (Match Score) для каждой вакансии и подсвечивает, каких навыков не хватает.

3.4. Детектор «фейковых» и висящих вакансий

• Задача: отслеживать вакансии, которые перепубликовываются каждую неделю месяцами без найма, и помечать их специальным бейджем «Подозрение на вечный поиск».

4. Основной функционал API (REST API)


4.1. Пользователи и авторизация

• Регистрация и вход (JWT: Access + Refresh токены).
• Привязка Telegram-аккаунта для получения уведомлений.
• Профиль кандидата: желаемая зарплата, формат работы, массив навыков, стоп-слова (например, исключить «стажировка» или «1С»).

4.2. Поиск и фильтрация

• Полнотекстовый поиск по заголовку и описанию.
• Фильтры: зарплата (с автоматической конвертацией валют по актуальному курсу), валюта, грейд, теги технологий, формат (удалёнка, гибрид, офис), страна/город, источник.
• Сортировка: по дате, по зарплате, по проценту совпадения с профилем (Match Score).
• Курсорная или постраничная пагинация.

4.3. Канбан-трекер откликов (CRM для кандидата)

• Возможность добавить вакансию в личный трекер.
• Смена статусов: Сохранено → Откликнулся → Тестовое → Интервью → Оффер / Отказ.
• Заметки к каждой вакансии и напоминания (например, «написать HR через 3 дня, если нет ответа»).

4.4. Мгновенные уведомления

• Настройка подписок по сложным фильтрам.
• Асинхронная отправка карточек новых подходящих вакансий в Telegram-бот с кнопками «В избранное» и «Скрыть».

5. Нефункциональные требования и архитектура

• База данных: PostgreSQL (использование JSONB для сырых ответов парсера, pg_trgm или pgvector для поиска дублей и семантического поиска).
• Кэширование и брокер: Redis для кэширования популярных поисковых запросов, курсов валют и работы очередей задач.
• Контейнеризация: весь проект (API, воркеры парсинга, планировщик, БД, Redis, бот) должен подниматься одной командой через docker-compose.
• Наблюдаемость (Observability): структурированные JSON-логи, эндпоинт /health и базовые метрики (сколько вакансий собрано за час, сколько ошибок парсинга по каждому источнику).
• Документация: автоматическая генерация OpenAPI / Swagger спецификации.

6. Этапы разработки (Roadmap)

1. MVP (Этап 1): схема БД, REST API для поиска вакансий, 1 парсер (через официальное API), запуск в Docker.
2. Расширение сбора (Этап 2): добавление очередей задач, парсера веб-страниц, нормализации зарплат и базовой дедупликации.
3. Умные фичи (Этап 3): подключение LLM для генерации саммари и тегов, расчёт Match Score с профилем пользователя.
4. Интерактив (Этап 4): Telegram-бот с уведомлениями и API для канбан-трекера откликов.
