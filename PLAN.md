# План: Next-Gen Job Aggregator

Цель: закрыть всё ТЗ и выйти за него там, где жюри это увидит: качество дедупа и матчинга подтверждено цифрами, проект запускается одной командой без ключей, всё объяснимо и наблюдаемо.

## 1. Стек (рекомендация)

| Слой | Выбор | Почему |
|---|---|---|
| Язык / API | Python 3.12, FastAPI, Pydantic v2 | Swagger из коробки, async, удобный LLM-стек |
| БД | PostgreSQL 16 + `pg_trgm` + `pgvector`, SQLAlchemy 2 (async), Alembic | Всё по ТЗ: JSONB, триграммы, векторы |
| Очереди | Celery + Redis, Beat как планировщик, Flower | Отдельная очередь на каждый источник даёт изоляцию воркеров |
| HTTP-сбор | httpx + tenacity (retry с backoff + jitter), ротация UA, token-bucket в Redis | Rate limit, ретраи |
| Бот | aiogram 3 | Inline-кнопки, deep-link привязка |
| LLM | Claude API (structured output через tool use) + офлайн-фолбэк на правилах | Работает и без ключа |
| Эмбеддинги | multilingual-e5-small локально (sentence-transformers) | Бесплатно, RU+EN |
| Наблюдаемость | structlog (JSON), Prometheus + Grafana (готовый дашборд), `/health` + `/ready` | Больше, чем «базовые метрики» |
| Качество | pytest + testcontainers, ruff, mypy, GitHub Actions, pre-commit | Показывает инженерный уровень |

## 2. Архитектура

Модульный монолит, кодовая база одна, процессы разные: `api`, `worker-collect-*`, `worker-enrich`, `worker-notify`, `beat`, `bot`, `postgres`, `redis`, `prometheus`, `grafana`, `flower`.

Пайплайн вакансии:

```
collect → raw_vacancies (JSONB, без изменений)
        → normalize (зарплата, валюта, формат, город, грейд по правилам)
        → dedup (кластеризация в каноническую вакансию)
        → enrich (LLM: стек, грейд, саммари, red flags, «вода»)
        → embed (pgvector)
        → match + notify (подписки → Telegram)
```

Каждый шаг идемпотентен (ключ = content hash), поэтому повторный запуск не плодит дубли и не тратит LLM повторно.

Коллекторы подключаются как плагины: `BaseCollector` с методами `fetch()` и `parse()`, регистрация через декоратор `@register("hh")`. Новый источник = один файл + строка в конфиге. Для каждого источника есть свой circuit breaker: после N ошибок подряд источник ставится на паузу, остальные продолжают работать.

## 3. Схема БД (основное)

- `sources`, `collector_runs` (журнал запусков: сколько собрано, ошибки, длительность)
- `raw_vacancies` (JSONB payload, source, external_id, fetched_at, content_hash)
- `companies` (нормализованное имя, алиасы, trust score)
- `vacancies`: каноническая сущность (title, description, tsvector, embedding, salary_from/to в исходной валюте и в RUB, grade, format, city, country, first_seen, last_seen, status)
- `vacancy_sources`: все ссылки на площадки для одной вакансии и причина склейки
- `skills` (словарь с синонимами: k8s → Kubernetes, «постгрес» → PostgreSQL), `vacancy_skills` (must / nice-to-have)
- `vacancy_enrichment` (summary JSON, red_flags[], water_score, model, prompt_version, cost)
- `repost_history` (fingerprint, даты появления), используется детектором «вечного поиска»
- `users`, `refresh_tokens` (ротация, детект повторного использования), `profiles`, `user_skills`
- `subscriptions` (сохранённый фильтр той же схемы, что поиск)
- `tracker_items`, `tracker_events` (история статусов), `reminders`
- `notifications_sent` (не шлём один кластер дважды), `currency_rates`

## 4. Как закрываем ТЗ и что сверх него

### Сбор (п. 2)
- hh.ru API, Habr Карьера (скрапинг), Telegram-каналы (веб-превью `t.me/s/...` без авторизации; MTProto через Telethon, если есть api_id).
- Сверх ТЗ: **demo/replay-режим**. Записанные фикстуры ответов источников позволяют жюри поднять проект без сети и ключей и сразу получить живые данные.

### Дедупликация (п. 3.1), многоступенчатая
1. Точный хеш: нормализованная компания + очищенный заголовок + топ-навыки.
2. Отбор кандидатов: `pg_trgm` similarity по заголовку внутри той же компании или окна дат.
3. Подтверждение: косинус эмбеддингов описания плюс совпадение зарплаты и города.
4. Объединение в кластер, в `vacancy_sources` сохраняется объяснение («склеено: title 0.91, embedding 0.88»).
- Сверх ТЗ: размеченный тестовый набор и отчёт **precision / recall** дедупа в README. Цифры убеждают сильнее слов.

### LLM-пайплайн (п. 3.2)
- Строгий JSON по схеме (tool use) с валидацией Pydantic и повтором при невалидном ответе.
- Кэш по content hash: дубли повторно не отправляются. Учёт токенов и стоимости, дневной бюджет.
- Сверх ТЗ: **water score 0–100**, нормализация стека по словарю синонимов, версионирование промптов, офлайн-фолбэк (regex + словарь), если ключа нет.

### Match Score (п. 3.3)
- Загрузка резюме PDF/DOCX → навыки (LLM или фолбэк).
- Взвешенный скор: must-have навыки > nice-to-have, грейд, зарплата, формат, стоп-слова. Ответ объяснимый: что совпало, чего не хватает, сколько баллов дал каждый фактор.
- Сверх ТЗ: **skill-gap аналитика** («выучи Kafka — откроется ещё 37 вакансий с match > 70%»).

### Детектор «вечных» вакансий (п. 3.4)
- Fingerprint, история перепубликаций, срок жизни, частота репостов → бейдж «Подозрение на вечный поиск».
- Сверх ТЗ: **trust score компании** (доля вечных вакансий, red flags, скрытые зарплаты).

### API (п. 4)
- JWT access + refresh с ротацией и детектом кражи refresh-токена, argon2, rate limit на auth.
- Привязка Telegram через deep-link с одноразовым токеном.
- Поиск: **гибридный** (FTS по русскому и английскому + семантический pgvector, слияние через RRF), все фильтры ТЗ, курсорная пагинация, сортировка по match score.
- Валюты: курсы ЦБ РФ с кэшем в Redis, все зарплаты дополнительно хранятся в RUB.
- Сверх ТЗ: **оценка зарплаты**, если она не указана (перцентили рынка по грейду и стеку), эндпоинты **аналитики рынка** (топ навыков, тренды, вилки по грейдам).
- Канбан: переходы статусов как state machine с валидацией, таймлайн событий, заметки, напоминания. Авто-напоминание «нет ответа 3 дня» уходит в Telegram.
- Подписки: тот же фильтр, что у поиска; режимы «мгновенно» и «дайджест», тихие часы. Карточка в боте с кнопками «В избранное», «Скрыть», «В трекер».

### Нефункциональные требования (п. 5)
- `docker compose up`: поднимается всё, включая миграции, сиды и Grafana с готовым дашбордом.
- `/health` (liveness) и `/ready` (БД, Redis, очередь); Prometheus-метрики: собрано за час, ошибки по источникам, латентность LLM, размер очередей.
- OpenAPI с примерами запросов и ответов, README с диаграммой архитектуры, ADR по ключевым решениям, Makefile.

## 6. Риски

- **hh.ru API**: доступ может требовать регистрацию приложения или токен. Фолбэк: demo-фикстуры.
- **Habr Карьера**: антибот или смена вёрстки. Парсер покрыт тестами на сохранённом HTML, при поломке срабатывает circuit breaker.
- **Telegram MTProto** требует api_id/hash. По умолчанию используем веб-превью `t.me/s/`.
- **Стоимость LLM**: кэш, дешёвая модель (Haiku), бюджет, обогащаются только новые кластеры.
